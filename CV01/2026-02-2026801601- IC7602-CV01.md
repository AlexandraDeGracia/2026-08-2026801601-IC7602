Preguntas:

1. ¿Por qué es importante usar rangos de IP (CIDR) que no se solapen?
Según el libro, la conectividad entre una VPC y las redes locales u otras VPC funciona mejor cuando cada red utiliza rangos de direcciones IP que no se solapan. Por eso, se recomienda asignar a cada VPC un bloque CIDR único, continuo y sin superposición.
Esto permite que el enrutamiento identifique correctamente las redes de destino y que el tráfico llegue a los recursos correspondientes. Si dos redes utilizan rangos de IP superpuestos, pueden presentarse conflictos de direccionamiento que impidan establecer correctamente la conexión. En particular, dos VPC no pueden establecer una conexión de VPC peering si sus bloques IPv4 CIDR principales se solapan.


2. ¿Cuál es la diferencia entre enrutamiento estático y dinámico (BGP) en una conexión AWS Site-to-Site VPN? ¿Qué ventaja ofrece el dinámico?
El libro explica que AWS Site-to-Site VPN admite tanto el enrutamiento estático como el dinámico.
- Enrutamiento estático: las rutas se configuran manualmente para indicar por dónde debe enviarse el tráfico hacia las redes de destino.
- Enrutamiento dinámico (BGP): utiliza sesiones de peering BGP para intercambiar información de enrutamiento entre AWS y los dispositivos de la red remota.
La principal ventaja del enrutamiento dinámico es que permite intercambiar rutas automáticamente y establecer prioridades, políticas y métricas para influir en la selección del camino que sigue el tráfico entre la red local y AWS. Esto facilita la administración del enrutamiento cuando existen varias rutas o conexiones.
Para utilizar BGP, el dispositivo de la red remota debe ser capaz de terminar tanto las sesiones IPsec como las sesiones BGP.


3. ¿Qué es AWS Transit Gateway y qué problema resuelve frente a conectar cada VPC por separado?
AWS Transit Gateway es un servicio administrado de AWS, altamente disponible y escalable, que funciona como un centro regional de tránsito de red para interconectar múltiples VPC y redes locales mediante una arquitectura de concentrador y radios (hub-and-spoke).
En lugar de establecer conexiones individuales entre cada par de VPC, cada VPC se conecta a Transit Gateway para acceder a las demás redes autorizadas y conectadas. De esta manera, se centraliza la configuración del enrutamiento y se simplifica la administración de la conectividad.
Además, permite segmentar el tráfico mediante tablas de rutas, asociaciones y propagaciones, así como centralizar servicios compartidos, como la inspección del tráfico y el acceso a determinados puntos de enlace.
El problema que resuelve es la complejidad de administrar numerosas conexiones individuales a medida que aumenta el número de VPC. El libro indica que Transit Gateway puede admitir hasta 5.000 conexiones o attachments.


4. ¿Qué es AWS Direct Connect, en qué se diferencia de una VPN por internet y cómo se puede proteger el tráfico si no está cifrado por defecto?
AWS Direct Connect permite establecer una conexión de red dedicada entre una red local y AWS. Esta conexión proporciona acceso privado a los recursos de AWS y puede reducir los costos de red, aumentar el ancho de banda y ofrecer un rendimiento más predecible que las conexiones basadas en internet.
La diferencia principal es que AWS Direct Connect utiliza una conexión de red dedicada, mientras que AWS Site-to-Site VPN establece una conexión VPN IPsec a través de internet. La VPN proporciona cifrado del tráfico mediante IPsec, mientras que Direct Connect no cifra el tráfico de forma predeterminada.
Para proteger el tráfico de Direct Connect, el libro presenta dos alternativas:
- MACsec: se puede utilizar como opción de cifrado en conexiones dedicadas de 10 o 100 Gbps.
- VPN IPsec sobre Direct Connect: para conexiones de 1 Gbps o menos, se pueden crear túneles VPN sobre la conexión dedicada. Esta combinación proporciona cifrado de extremo a extremo mediante IPsec y conserva las ventajas de rendimiento de Direct Connect.


5. ¿Cómo funciona Site-to-Site VPN CloudHub y en qué situación conviene utilizarlo?
Site-to-Site VPN CloudHub es una solución de conectividad que utiliza una arquitectura de concentrador y radios (hub-and-spoke) para permitir la comunicación segura entre diferentes oficinas o sedes remotas.
Funciona mediante un virtual private gateway de Amazon VPC conectado a múltiples dispositivos de puerta de enlace de las sedes remotas. Cada puerta de enlace utiliza un número de sistema autónomo (ASN) de BGP único. Las redes remotas anuncian sus rutas mediante BGP y estas rutas se reciben y vuelven a anunciar a los demás pares BGP, permitiendo que las sedes envíen y reciban datos entre sí.
Las redes de las sedes no deben tener rangos de IP superpuestos.
Esta solución conviene cuando una organización tiene varias sucursales que ya disponen de conexiones a internet y necesita establecer comunicación entre ellas mediante una arquitectura centralizada, potencialmente de bajo costo, para conectividad principal o de respaldo. Puede utilizarse con una VPC o sin ella.
